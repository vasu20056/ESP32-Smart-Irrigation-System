1. Project Overview

1.1 System Description

The ESP32 Smart Irrigation System is an advanced automated watering solution featuring 9 capacitive soil moisture sensors arranged in a 3×3 grid, intelligent topology-based irrigation control, and a comprehensive web dashboard for real-time monitoring and reporting.

✅ Production Ready System
Version 4.2.4 includes all bug fixes, optimizations, and enhancements. Ready for field deployment.

2. Key Features

2.1 Intelligent Irrigation Control

BFS Topology Algorithm

The system uses a Breadth-First Search (BFS) algorithm to detect clusters of dry sensors. Irrigation is triggered only when 3 or more connected sensors are dry, preventing over-watering from isolated sensor failures.

Algorithm:
1. Mark all sensors as unvisited
2. For each unvisited dry sensor:
   - Start BFS traversal
   - Add neighbors within 15 units distance
   - Count cluster size
3. If cluster ≥ 3 sensors → Trigger irrigation
4. If cluster = 1 sensor → Log as isolated (no action)

Spatial Gradient Analysis

Compares moisture levels between top row (Y=30) and bottom row (Y=10) sensors to detect drainage patterns, blockages, or slope issues.

Isolated Sensor Detection

Single dry sensors are logged but don't trigger irrigation, preventing wasteful watering from sensor malfunctions.

5.2 Calibration Procedure

Step 1: Calibrate DRY Value

  1. Remove one sensor from soil and let it air dry for 2-3 minutes
  2. Open Serial Monitor (115200 baud)
  3. Note the ADC value (e.g., 3500)
  4. Send command: CONFIG_DRY:3500

Step 2: Calibrate WET Value

  1. Submerge the same sensor in water for 30 seconds
  2. Note the ADC value (e.g., 1200)
  3. Send command: CONFIG_WET:1200

Step 3: Set Thresholds

  1. Set dry threshold (trigger irrigation): CONFIG_DRY_THRESH:3000
  2. Set wet threshold (stop irrigation): CONFIG_WET_THRESH:1500
Tip: DRY_THRESHOLD should be between WET_THRESHOLD and CALIBRATION_DRY. Typical value is ~80-85% of CALIBRATION_DRY.

6. System Operation

6.1 State Machine

The system operates in one of four states:

MONITORING → IRRIGATING → WAITING → [cycle repeats]
     ↓            ↓
SYSTEM_FAULT (emergency stop)

State 1: MONITORING

  • Default state, checks sensors every 60 seconds
  • Analyzes topology using BFS algorithm
  • Triggers irrigation if 3+ connected dry sensors detected
  • Monitors for leaks and anomalies
  • Performs gradient analysis (top vs bottom row)

State 2: IRRIGATING

  • Pump turns ON
  • Checks moisture every 10 seconds
  • Minimum runtime: 5 minutes (prevents short-cycling)
  • Stops when all sensors < WET_THRESHOLD
  • Maximum runtime: 1 hour (failsafe timeout)
  • Monitors for irrigation failure (soil not getting wetter)

State 3: WAITING

  • Pump is OFF
  • 4-hour cooldown period
  • Prevents over-watering and pump wear
  • Monitors for unexpected dry/wet conditions
  • Returns to MONITORING after wait period

State 4: SYSTEM_FAULT

  • Pump is OFF (forced shutdown)
  • Triggered by critical errors:
    • Irrigation failure (no moisture change after 3 checks)
    • Maximum pump time exceeded without soil wetting
  • Requires manual reset: FORCE_RESET command

6.2 Operational Flow

  1. System Boot:
    • Connects to WiFi
    • Loads configuration from SPIFFS
    • Runs Power-On Self-Test (POST)
    • Enters MONITORING state
  2. Every 60 Seconds (MONITORING):
    • Reads all 9 sensors
    • Checks for leaks (≥98% moisture)
    • Analyzes topology (BFS cluster detection)
    • Checks gradient (top vs bottom)
    • Triggers irrigation if 3+ dry cluster found
  3. Irrigation Cycle (IRRIGATING):
    • Turns pump ON
    • Checks sensors every 10 seconds
    • Runs for minimum 5 minutes
    • Stops when all sensors wet
    • Maximum 1 hour (failsafe)
    • Enters WAITING state
  4. Cooldown (WAITING):
    • Pump OFF for 4 hours
    • Monitors for anomalies
    • Returns to MONITORING
  5. Daily (Midnight):
    • Generates daily report
    • Resets daily counters
    • Accumulates to monthly totals
    • Saves to flash memory
  6. Monthly (30 Days):
    • Generates monthly report
    • Resets monthly counters
    • Saves to flash memory

9. Advanced Algorithms

9.1 BFS Topology Detection

The system uses Breadth-First Search to detect connected clusters of dry sensors:

Algorithm Steps:
1. Initialize all sensors as unvisited
2. For each unvisited dry sensor (value > DRY_THRESHOLD):
   a. Create empty queue
   b. Add sensor to queue and mark as visited
   c. Initialize cluster size = 0
   d. While queue not empty:
      - Dequeue sensor
      - Increment cluster size
      - For each neighbor (distance ≤ 15 units):
        * If neighbor is dry AND unvisited:
          - Add to queue
          - Mark as visited
   e. Log cluster information
3. If any cluster size ≥ 3 → Trigger irrigation
4. If cluster size = 1 → Log as isolated (no action)

Neighbor Detection

Two sensors are neighbors if their Euclidean distance ≤ 15 units:

distance = sqrt((x2 - x1)² + (y2 - y1)²)

Example:
Sensor 0 (10,10) and Sensor 1 (20,10):
distance = sqrt((20-10)² + (10-10)²) = sqrt(100) = 10 ✓ Neighbors

Sensor 0 (10,10) and Sensor 8 (30,30):
distance = sqrt((30-10)² + (30-10)²) = sqrt(800) = 28.3 ✗ Not neighbors

Why 3-Sensor Minimum?

  • Prevents false triggers from single sensor failures
  • Ensures meaningful dry area before watering
  • Balances water conservation with adequate coverage
  • Isolated sensors logged for diagnostics but don't trigger irrigation

9.2 Gradient Analysis

Compares top row vs bottom row moisture to detect drainage issues:

Algorithm:
1. Calculate bottom row average:
   bottomAvg = Average(Sensor 0, Sensor 1, Sensor 2)  // Y=10

2. Calculate top row average:
   topAvg = Average(Sensor 6, Sensor 7, Sensor 8)  // Y=30

3. Check gradient:
   if |topAvg - bottomAvg| > 30%:
      → Warning: Significant gradient detected
      → Check for blockage, poor drainage, or slope issues

Interpretation

  • Top wet, Bottom dry: Possible blockage preventing water flow downward
  • Top dry, Bottom wet: Normal drainage (water flows downhill)
  • Uniform moisture: Good water distribution

9.3 Leak Detection

Algorithm (runs during MONITORING and WAITING states):
For each sensor:
  if moisture% ≥ LEAK_THRESHOLD_PERCENT (98%) AND pump is OFF:
    → ALERT: Potential leak detected at sensor location
    → Log sensor position (X,Y coordinates)
    → Continue monitoring (does not enter FAULT state)

Why Not in IRRIGATING State?

High moisture is expected during irrigation. Leak detection only runs when pump is OFF to avoid false positives.

9.4 Irrigation Failure Detection

Algorithm (runs during IRRIGATING state):
1. Read all sensors every 10 seconds
2. Calculate currentMoistureSum = Sum of all 9 sensor ADC values
3. Compare to previousMoistureSum:
   if currentSum ≥ previousSum:  // Not getting wetter (lower ADC = more moisture)
      failureCount++
      if failureCount ≥ 3:
         → SYSTEM_FAULT: Irrigation failure
         → Turn pump OFF
         → Require manual reset
   else:
      failureCount = 0  // Reset counter if improving
4. Update previousMoistureSum = currentMoistureSum

Why 3 Consecutive Checks?

Allows time for water to reach sensors (travel time through soil). Single check might give false positive during normal operation.

10. Troubleshooting

10.1 WiFi Connection Issues

Symptoms

WiFi connecting...........
WiFi connection failed!
Operating without WiFi.

Solutions

  1. Verify SSID and password are correct (case-sensitive)
  2. Ensure WiFi is 2.4GHz network (ESP32 doesn't support 5GHz)
  3. Check router is powered on and broadcasting
  4. Move ESP32 closer to router (reduce distance)
  5. Verify router allows new device connections
  6. Try different WiFi network for testing

10.2 Sensor Reading Issues

Symptoms: Sensor Reads 0 or 4095

Reading Likely Cause Solution
0 No power to sensor Check VCC connection to 3.3V
0 Sensor shorted to GND Check for shorts in wiring
4095 Signal wire disconnected Verify signal wire to MUX or GPIO 35
4095 Floating pin (nothing connected) Connect sensor or add 10kΩ pull-down resistor

Symptoms: Sensor 8 Not Working

⚠️ Remember: Sensor 8 connects directly to GPIO 35, NOT through the multiplexer!
  1. Verify GPIO 35 is input-only (cannot be configured as output)
  2. Check direct connection from Sensor 8 signal to GPIO 35
  3. Confirm ADC attenuation is set: analogSetPinAttenuation(SENSOR_9_PIN, ADC_11db)
  4. Test with different sensor to rule out hardware fault

Symptoms: Multiplexer Channels Mixed Up

Wrong sensor triggers irrigation or readings swap

  1. Verify CD4051 pin connections:
    • S0 (Pin 11) → GPIO 19
    • S1 (Pin 10) → GPIO 18
    • S2 (Pin 9) → GPIO 21
  2. Check Y# connections match code mapping (see Section 3.3)
  3. Run POST and verify mapping: Check Serial Monitor output at boot

10.3 Relay Not Switching

Symptoms

Manual PUMP_ON command received.
(No relay click sound)

Solutions

  1. Check GPIO 23 connection to relay IN pin
  2. Verify relay VCC connected to 5V (not 3.3V - may not trigger reliably)
  3. Test relay with external 5V power source
  4. Check relay LED indicator (should light when ON)
  5. Measure voltage at GPIO 23 with multimeter (should be ~3.3V when ON)
  6. Try different GPIO pin if GPIO 23 is damaged

10.4 Pump Runs But No Water

Symptoms

Pump turned ON.
!!! WARNING: Soil is not getting wetter! (Check 1)

Solutions

  1. Verify pump power supply voltage is correct (12V for most pumps)
  2. Check water source is not empty
  3. Inspect pump intake filter for clogs
  4. Examine water lines for leaks or kinks
  5. Test pump separately with direct power connection
  6. Verify relay is switching high-voltage side correctly (check with multimeter)
  7. Listen for pump motor running (should hear humming)

10.5 Irrigation Never Triggers

Symptoms

Sensors show dry values but irrigation doesn't start

Solutions

  1. Test cluster detection manually: 
    S0:3500
S1:3500
S3:3500
FORCE_CHECK
    Should trigger: TOPOLOGY ALERT: Dry cluster of 3 - triggering irrigation!
  2. Verify thresholds are logical:
    • DRY_THRESHOLD must be < CALIBRATION_DRY
    • Example: DRY=3000, CALIBRATION_DRY=3500 ✓
  3. Check cluster size requirement:
    • MIN_DRY_SENSORS_TO_TRIGGER should be 3 (default)
  4. Verify sensors are neighbors:
    • Distance must be ≤ 15 units
    • Check sensor coordinates in code match physical layout

10.6 System in FAULT State

Symptoms

State: SYSTEM_FAULT

Causes

  1. Irrigation Failure: Soil not getting wetter after 3 consecutive checks
  2. Max Pump Time: Pump ran for 1 hour without adequate soil wetting

Recovery Steps

  1. Check Serial Monitor for specific error message
  2. Fix underlying issue (pump malfunction, sensor error, etc.)
  3. Send recovery command: FORCE_RESET
  4. System returns to MONITORING state
  5. Monitor for recurrence
